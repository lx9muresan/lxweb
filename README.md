# lxmuresan — photography portfolio

A minimal static photography portfolio. No framework, no build server — just a Node script that optimizes your photos and writes a small JSON manifest.

## Folder layout

```
.
├── index.html            # site entry
├── styles.css
├── layouts.js
├── app.jsx               # React app (babel standalone transpiles in-browser)
├── build.mjs             # image optimizer + manifest generator
├── collections.json      # (optional) order + display names of collections
├── package.json
├── vercel.json
└── photos/
    ├── quiet-cities/     # ← drop your raw photos here
    │   ├── 01.jpg
    │   └── 02.jpg
    ├── people/
    ├── nature/
    ├── interiors/
    └── optimized/        # ← generated by `npm run build` (gitignored)
        └── <collection>/
            ├── <name>-thumb.webp   # ~640px wide, for home + collections grid
            └── <name>-full.webp    # ~1600px wide, for carousel
```

## Add a collection of photos

1. Create a folder under `photos/` whose name is the collection slug (lowercase, hyphens for spaces). e.g. `photos/street-tokyo/`.
2. Drop your photos inside. JPG / PNG / WebP / TIFF all work. Filenames don't matter — they'll be slugified for the output.
3. **(Optional)** add the collection to `collections.json` to control order + display name:
   ```json
   [
     { "id": "quiet-cities", "name": "quiet cities" },
     { "id": "street-tokyo", "name": "street tokyo" }
   ]
   ```
   If `collections.json` is missing or a folder isn't listed, the site falls back to alphabetical and derives display names from slugs.
4. Run the build (see below).

**Orientation:** portrait, landscape, and square all work — each image keeps its native aspect. The site reads dimensions from every optimized file during the build and writes them into `photos.json`.

## Build (local)

```bash
npm install     # installs sharp, once
npm run build   # regenerates photos/optimized/ + photos.json
```

The build script is incremental — it only re-encodes files whose source has changed since the last run.

## Run locally

```bash
npm run dev     # runs build, then serves on localhost
# or without a fresh build:
npm run serve
```

Open http://localhost:3000 (or whatever port `serve` chooses).

## Deploy to Vercel

1. `git init && git add . && git commit -m "initial"`
2. Push to GitHub.
3. On vercel.com, **New Project** → import the repo. Leave all defaults — `vercel.json` already configures the build.
4. Vercel runs `node build.mjs` during deployment. The generated `photos.json` + optimized images are served as static assets with long-lived cache headers.

Subsequent deploys: add photos locally, commit, push. Vercel re-runs the build.

### Why isn't `photos/optimized/` checked into git?

Because it can be derived from the raw photos and would bloat the repo. Vercel regenerates it on every deploy. If you prefer to avoid the build-time dependency, remove `photos/optimized/` from `.gitignore`, run `npm run build` locally, commit the output, and remove `buildCommand` from `vercel.json`.

## Adjust image sizes

Edit the `THUMB` and `FULL` constants at the top of `build.mjs` to change output resolution or WebP quality. Defaults: 640px @ q78 (thumb) and 1600px @ q82 (full).

## Tweak the design

- **Background color** — `--bg` in `styles.css`.
- **Bio copy** — `BIO` constant in `app.jsx`.
- **Nav brand text** — the literal "lxmuresan" in `app.jsx`.
- **Collection cluster geometry** — `groupedLayout` in `layouts.js` (padding, columns per cluster, jitter, etc).

## Notes

- This is a fully static site. No API, no backend. You can host it anywhere that serves static files (Vercel, Netlify, Cloudflare Pages, GitHub Pages, S3+CloudFront).
- The site loads React + Babel standalone from unpkg for simplicity. If you later want a fully self-contained bundle, run the JSX through a real build step and replace the `<script type="text/babel">` tag with a precompiled file.
